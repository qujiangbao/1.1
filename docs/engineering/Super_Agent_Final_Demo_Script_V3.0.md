## 零、演示前准备（必读）

### 环境检查清单

| # | 检查项 | 命令/操作 | 预期 |
|:---:|-------|----------|:---:|
| 1 | 后端启动 | `cd /mnt/d/广智能/backend && .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000` | health: healthy |
| 2 | 前端启动 | Windows PowerShell: `cd D:\广智能\frontend && npm run dev` | localhost:3000 |
| 3 | DeepSeek API | `curl -s http://localhost:8000/api/v1/health` | healthy |
| 4 | 预热 LLM | 提前 10 分钟跑一次 agent/chat，让连接池热起来 | < 15s |
| 5 | 浏览器隐身窗口 | Chrome 无痕模式，干净无插件 | 全屏 |
| 6 | 网络 | 关闭 VPN/代理（如果有） | 直连 |

### 故障预案

| 故障 | Plan B |
|------|--------|
| DeepSeek 超时 | LLM Gateway 自动 fallback → 关键词兜底模式 |
| 前端白屏 | 直接展示后端 API 响应（curl + 终端） |
| 网络全断 | 本地录制 Demo 视频备选 |
| 页面加载慢 | 提前打开所有标签页，只做切换不做加载 |

## 第三幕：核心任务——Supervisor 调度 (1:00-2:00)

```

00:00.5  👔 Supervisor → 调度 IndustryAgent（先搞清产业方向）

00:02.5  👔 Supervisor → 收到产业分析 → 并行调度 Investment + Risk + Policy

00:03.0  🛡️ RiskAgent → 批量风险评估（并行）
00:03.0  📋 PolicyAgent → 政策匹配（并行）

00:12.0  📋 PolicyAgent → 政策建议生成

00:14.0  📊 BIAgent → 数据可视化
00:14.8  ✅ 完成
```

### 台词（在 Agent 执行期间穿插）

> "注意看右侧面板——

（Supervisor 点亮时）
> 运营总经理先理解我的意图，拆成 5 个子任务。

（3 个 Agent 同时点亮时）
> 现在招商经理、风险分析师、政策顾问**同时开工**——因为它们互不依赖。这是 Multi-Agent 的核心优势：真正的并行执行。

## 第五幕：Agent Trace——可解释性 (2:30-3:30)

### 画面
- 点击"查看执行链路"→ 进入 Trace DAG 页面（`/agent/trace/xxx`）
- DAG 图展示：
  ```
  Supervisor
    ├─→ IndustryAgent (串行)
    └─→ [InvestmentAgent, RiskAgent, PolicyAgent] (并行)
         └─→ BIAgent (汇总)
  ```

### 台词（这一节是技术评委最关注的，节奏放慢）

> "评委可能会问：这是不是一个 LLM 在假装多个 Agent？

（鼠标悬停在 Supervisor 节点，弹出：意图、子任务列表、路由决策）

> 请看决策链路。每一步都可点击查看。

（点击 IndustryAgent 节点 → 展示输入/输出/工具调用/耗时）

> Supervisor 决定先调 IndustryAgent——因为产业方向必须先搞清楚。
> 这不是硬编码的 if-else，这是 LLM 推理出的任务依赖图。

（点击 InvestmentAgent 节点）

> 然后并行调度 Investment、Risk、Policy——因为它们互不依赖。
> 注意：这三个 Agent **同时执行**，不是顺序执行。
> 这是单 LLM 做不到的——它只能假装并行，实际还是串行。

（点击 PolicyAgent 节点 → 展示内部 Tool 调用记录）

> 每个 Agent 内部的工具调用也全记录——调了什么数据库、什么 API、耗时多少。
> 这对于企业客户来说至关重要：**每一份 AI 生成的报告，都可以追溯到原始数据源。**"

### 关键动作
- 点击至少 3 个节点，展示不同的信息维度
- 强调"并行执行"的时间戳证据
- 最后回到完整 DAG 全景图

### 评委心理锚点
> "可审计、可解释、真并行" → 技术壁垒建立

## 十、演示者备忘录

1. **不要解释，要展示**。让屏幕说话。你的台词是导航，不是说明书。
2. **控制节奏**。让评委有时间消化视觉信息。沉默 2 秒比填满 2 秒更有力。
3. **眼神**。关键句子（结尾、金句）要和评委眼神接触，不要看屏幕。
4. **如果 Agent Chat 超时**。面不改色地说"大模型调用需要约 15 秒，我们正好利用这段时间看一下 Agent 团队的架构"——把等待变成讲解窗口。
5. **如果 Demo 全崩**。切到 Plan B：打开 Trace 历史记录页面，播放之前保存的 Demo 录像（提前录制）。诚实说"现场网络不稳定，这是之前录制的同一次执行"——评委尊重诚实。
6. **自信**。你们有一个真正的 Multi-Agent 系统。绝大多数参赛队只有一个 Chatbot 套壳。你们的技术壁垒是真实的。
