项目已达到“单园区、单节点、内网试运行”的技术条件。核心页面、数据库、权限、政策更新、资料导入、招商闭环、企业服务工单、备份恢复和证据边界均可运行。系统已禁止生产环境演示数据和未接入工具伪造成功。

## 仍需外部或人工完成

1. **政策规则人工审核**：当前没有 `REVIEWED` 规则。政策负责人必须对原文和有效期负责；系统不能代签审核责任。目标天河政策现有 1 条产业范围草稿可先审核。
2. **权威企业数据源**：本地快照可试运行，但工商、知识产权、司法风险、联系人和动态经营数据覆盖不足。需要采购合规 API、取得政府数据授权，或持续按资料模板导入。
3. **正式申报细则**：目标政策是原则性措施，资金池上限不是单家企业门槛。需等主管部门发布实施细则/申报指南后更新政策并提取具体条件。
4. **公网基础设施**：需要用户提供服务器、正式域名、TLS 证书、DNS、网络访问策略和备案条件；仓库的 8080 HTTP 只适用于本机或内网。
5. **异地备份和告警渠道**：本地备份已经可用，但还需用户指定加密对象存储/NAS、保留周期，以及短信、邮件、企业微信或其他告警接收人。
6. **合规责任确认**：需园区确定数据负责人、企业资料授权依据、个人信息最小化范围、保留期限和删除审批流程，并完成正式法律审查。
7. **扫描件 OCR 与恶意文件扫描**：当前图片型 PDF 不识别。生产若允许外部企业上传，需要部署 OCR 和 ClamAV/同类扫描服务并配置资源预算。
8. **多园区隔离**：当前是单园区部署。若未来一个实例服务多个园区，必须先确定租户模型，再为所有业务表、对象存储路径、向量检索和审计记录增加强制 `park_id` 隔离。
9. **运营配置**：需创建真实工作人员账号，分配招商、政策、企业服务角色、负责人和 SLA；这属于组织决定，不能由系统猜测。

## 建议的试运行顺序

1. 由政策负责人审核目标政策的 1 条产业范围草稿。
2. 使用 CSV/XLSX 模板继续导入企业台账，优先补统一社会信用代码、经营范围、工商状态、注册资本、专利数和来源。
3. 用“查看匹配企业”核验满足、明确不满足和待补证三类结果。
4. 用 3—5 个真实企业诉求试跑服务工单，并确认负责人和办结规则。
5. 配置每日备份与外部告警，完成一次隔离环境恢复演练后再开放公网。
