# 政策更新中心使用说明

## 功能位置

使用初始 `admin` 登录后，进入：

`资源治理 → 政策更新中心`

也可以在“惠企政策库”点击“政策更新中心”。

## 权限规则

- 初始 `admin` 是政策更新功能所有者，可以执行增量更新、强制刷新、审批和撤销授权；
- 后续创建的超级管理员默认不能运行爬虫，只能提交使用申请；
- 申请必须由初始 `admin` 批准；
- 获批超级管理员可以执行普通增量更新，不能执行强制刷新；
- 产业园经理、政策经理和其他角色不能访问政策更新中心；
- 数据库认证关闭、数据库异常或授权状态无法确认时，系统拒绝执行爬虫。

## 更新流程

1. 选择每个来源扫描的列表页数，默认3页；
2. 选择并发数，最大3，避免对政府网站产生过大压力；
3. 点击“开始更新”；
4. 系统在后台依次完成政府白名单来源发现、正文抓取、去重、目录发布和数据库/向量同步；
5. 页面每3秒刷新一次运行状态，可离开页面后再返回查看；
6. 运行结果会显示新增抓取、未变化、重复转载、版本关系和失败数量。

普通增量更新会跳过7天内已经成功抓取的正文。强制刷新只供初始 `admin` 使用。

## 去重规则

系统按以下顺序识别重复：

1. 规范化URL：统一HTTPS、去除查询参数和锚点、合并移动版地址；
2. 规范化政策文号：同一文号视为同一政策的不同来源；
3. 标准化正文哈希：去除网页来源头、URL和无意义空白后比较；
4. 同标题、同发布日期或正文高度相似：识别跨部门转载；
5. 同标题但文号不同：保留为政策版本关系，不自动删除；
6. 相似但无法确定的记录只计入“疑似重复”，不自动合并。

重复政策的原始网页和抓取文件会继续保留用于审计，但只有主政策进入Policy Agent目录。

## 与资格规则审核的关系

爬虫权限、重复政策审核和资格规则人工复核是三项独立控制：

- 爬虫授权决定“谁可以更新政策”；
- 去重决定“哪些网页属于同一政策或不同版本”；
- 资格规则审核决定“哪些申报条件真实来自政策原文”。

当政策正文哈希发生变化时，系统保留原有资格规则内容，但会把其中所有 `REVIEWED` 状态自动改回 `DRAFT`，同时清除原复核人和复核时间。审核人员必须根据新正文重新复核后，规则才能再次参与确定性企业资格判断。

## 数据与配置

- 内置来源配置：`backend/app/data/guangzhou_policy_sources.json`
- 政策缓存：由 `POLICY_CRAWL_DATA_DIR` 指定
- Crawl4AI服务：由 `POLICY_CRAWLER_API_URL` 指定；不可用时自动回退到政府网页直接正文提取
- Crawl4AI令牌：`POLICY_CRAWLER_API_TOKEN`
- 增量缓存天数：`POLICY_CRAWLER_REFRESH_DAYS`

所有来源必须是广州政府官方域名。页面不提供任意URL输入，避免服务器端请求伪造和非授权采集。

## 审计记录

每次更新保存：

- 操作者账号；
- 创建、开始和完成时间；
- 扫描页数、并发数和是否强制刷新；
- 抓取、未变化、失败、去重、版本和入库统计；
- 错误信息及“成功/部分完成/失败”状态。

同一时间只允许一个更新任务处于等待或运行状态。
